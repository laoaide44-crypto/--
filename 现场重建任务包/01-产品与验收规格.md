# 01 · 产品与验收规格（餐饮单场景）

> 本规格用于：指导重建、判定验收。描述的是**行为与数据约定**，不依赖任何具体源码路径；实现语言/文件划分自由，但下列行为与口径必须逐条成立。

---

## 0 · 一页概览

- **服务对象**：做交付的人——咨询顾问、现场交付工程师。
- **使用时机**：**访谈之后、写方案之前**。
- **核心价值**：AI 已经能干活了，但**没人能验收它干的活**——本产品把「验收」做成产品：
  **每一项都能判真假、每个数字都能复算、证据不够它敢说停。**
- **一句话演示收尾**：同一套规则，**证据一变，判断、测算、试点范围全部重算**。

## 1 · 端到端流程（餐饮一条线）

| # | 步骤 | 用户看到什么 | 关键纪律 |
|---|---|---|---|
| 1 | 丢材料 | 输入框 +「用示例材料」+「抽取事实 →」 | 材料脱敏；示例材料为合成 |
| 2 | 抽取事实 | 「引用定位 N/N」逐条出处、三层校验分列、不知道的清单 | **找不到原句就降级**，不装作有效 |
| 3 | 只问该问的 | 材料已答的（带原句）不再问；必须问的按优先级列出（为什么问/答了改变什么/从哪拿） | 问什么、怎么排序**由确定性规则决定**，不交给模型 |
| 4 | 三个数 | 门店数 / 单店月流水 / 单店员工数（+可选：兼职占比）；来源标注「材料预填 / 客户自报 / 默认假设」 | 默认值只是假设，**不能当客户回答** |
| 5 | 报告 | 顶部状态条（算出来的）、候选问题 A/B（不预设）、「假设情景」金额、复算步骤、停止条件 | 状态由**可检查条件**计算，不由模型或措辞升级 |
| 6 | 一次只问一件事（可选） | 逐题问答；回答进统一事实记录；可跳过 | 跳过不阻断流程 |
| 7 | 契约草稿 + 导出 | 11 块正文 + 附录 A–F；下载文件与页面**同源同内容** | 验收标准出现「提升/优化/增强」即作废重写 |
| 8 | 补证据 · 改决策 | 应用合成情景 → 变化报告（之前/之后/**依据**）→「↩ 撤回补充证据」复原 | 结论走**同一计算链重算**，不按情景名称硬编码 |
| 9 | 离线演示 | 「演示模式 — 捕捉于 …」显著标注 | **不冒充实时**；契约附录同步标注 |

**标注纪律（三种状态互不混读）**：【现场】= 现场实时生成；【预跑】= 联网时跑过、存下来的离线结果；【合成】= 合成演示材料。界面上每种都要如实标注。

## 2 · 数据约定

### 2.1 统一事实记录（Fact）

| 字段 | 约定 |
|---|---|
| ID | 由事实内容生成，**稳定**：同一句话在多次运行里 ID 不变（撞号自动加后缀） |
| text / quote | quote 必须**逐字**出自材料（不超过约 60 字）；归一化（全角→半角、去引号空白）后能在原文找到 |
| 材料位置 | 聊天记录格式=「时间 + 发言人」；普通文本=段落/行编号 |
| 来源类型 | 客户材料 / 公开资料 / 内部数据（这东西**从哪来**） |
| 状态 | 直接陈述 / 待确认 / 推断 / 已实测（它**有多硬**；不因更正或展示而升级） |
| 回指校验 | quote 通不过校验 → 打标「无法回指」并**降级为推断**，不得当事实用 |
| 原句支持 | 完全支持 / 部分支持 / 待逐字核对；**部分支持**时，未被原句覆盖的部分记入「未覆盖部分（待验证推断）」 |
| 适用于本客户 | 默认「待客户确认」；只有实测类才可能「已适用实测」 |
| 确认状态 | 默认「待确认」；**客户确认/更正是显式动作**，模型不得代为确认 |
| 备注 | 合成 / 预跑等标注位 |

### 2.2 来源与等级

- **来源类型**（从哪来）：客户材料 / 公开资料 / 内部数据。
- **来源等级**（有多硬）：`PUBLIC` 公开可查 ｜ `INTERVIEW` 现场访谈 ｜ `INTERNAL` 客户内部 ｜ `ASSUMPTION` 自定假设。
- 纪律：
  1. 不同来源的数字**不可混用**（例：「灵活用工渗透率 27%」是**企业采用比例**，不是兼职员工人数占比）；
  2. **更正不改变来源等级**（更正 ≠ 已验证）；
  3. 合成数据参与时，来源行必须带「合成」标注。

### 2.3 三层校验（分开记录，不能互相自动升级）

1. **原句是否存在**（可在原文定位）；
2. **原句是否支持结论**（完全 / 部分）；
3. **结论是否适用于当前客户**（默认「待客户确认」）。

### 2.4 修订（明确更正）

**条件（三者同时满足）**：同一来源（同一发言人）+ 明确更正表述（更正 / 纠正 / 说错 / 作废 / 改口 / 修正 / 以…为准 / 老数据 / 过时 等）+ 同一对象（去数字后存在公共词）。
**处理**：建立「**已更正（替代关系）**」——旧值保留在历史记录、**新值进入当前计算**、不再列为冲突；展示「✅ 已更正（替代关系）」。
**纪律**：更正只建立替代关系，**不等于新值已核实**；来源等级保持原级。

### 2.5 冲突与线索

- **待核实冲突**：不同来源互相矛盾 / 无明确更正表述 / 对象或范围存疑 → **保留冲突**，不擅自覆盖、不取平均；注明「需在同一对象、同一时间、同一口径下当面核实」。
- **落地失败 / 异常线索**：「买过 / 采购过某工具，但没人用 / 闲置 / 看不懂」这类**时序上的失败经历**——不是矛盾，是线索；单列为「落地失败线索」。
- ⚠️ **反例纪律**：「因预算停用软件」**不得**写成「因为不可解释而停用」——不得凭空造因果。

### 2.6 候选问题（不预设结论）

候选以清单出现，每条包含：**主张 / 支持证据 / 反向证据 / 未知项 / 建议验证动作 / 当前状态**。
两个容器（餐饮）：
- **A · 排班耗时、解释困难与返工**；
- **B · 用工结构可能存在优化空间**。

**状态取值（全集）**：
| 状态 | 含义 |
|---|---|
| 材料直接支持 · 建议进入试点设计 | 有直接支持的原句 |
| 需客户数据验证 | 缺关键数据，先取基线 |
| 证据不足 · 暂不建议进行该改造 | 允许说「不」 |
| 已被客户否定 | 客户明确否定后保留展示，不再推进 |
| 存在反向证据，需核实 | **客户陈述级**反向证据（未附数据） |
| 数据支持无可释放工时 · 停止该改造建议 | **数据级**反向证据 → 停止 |

**反向证据分三级（按来源，不按措辞升级）**：客户陈述 < 内部数据支持 < 实际试点验证。
**整体建议规则**：没有活跃候选 →「暂不建议，先补证据」；有 →「建议推进：…；**收益结论一律标『假设情景』，不作为承诺**」。

### 2.7 证据门槛（状态算出来，不是写出来）

**四个状态（只能按条件往上走）**：`待补证据 → 可设计试点 → 待验收实测 → 已完成试点验证`
**升级条件（全部可检查）**：
1. 有客户材料；
2. 关键参数**由客户给出**（≠ 默认值）；
3. 材料覆盖决策需要的字段（角色 / 问题 / 失败经历 / 口径）；
4. 有可判真假的**基线**；
5. 口径对齐（客户口径 vs 公开口径含义一致）。

**各状态允许 / 不允许（页面、契约、下载、摘要共用同一份）**：
| 状态 | 可以做 | 不可以做 |
|---|---|---|
| 待补证据 | 出「试点设计草案」；列候选与验证动作 | 给确定性收益；进入承诺；声称批准/签约 |
| 可设计试点 | 定试点范围与验收办法；约定停止条件 | 给确定性收益；声称批准/签约 |
| 待验收实测 | 按验收办法实测；记录结果 | 声称收益已实现；声称批准/签约 |
| 已完成试点验证 | 引用实测结果；据此谈扩大范围 | 视作客户批准；视作签约 |

**纪律**：**收到材料 ≠ 证据充分**；缺基线只允许出「试点设计草案」；**客户批准是独立开关，永不由实测自动置位**。

### 2.8 试点（范围与停止）

- **试点范围**由候选状态与证据**算出**（示例口径）：
  - 数据级反向证据 →「排班解释与返工试点（不做工时结构改造）」；
  - 陈述级反向证据待核实 →「用工结构改造暂停；先解决排班可解释 + 减少返工」；
  - 数据支持部分时段冗余 →「单店验证：午市时段试点 + 服务质量约束（最低在岗人数、出餐时效、满意度）」；
  - 证据不足 →「待补证据 —— 暂不定试点范围」。
- **停止条件**（出现任一即停）：实测显示可释放工时接近 0；服务质量劣化；一线抵触导致试运行无法持续；客户不批准 / 不签约。

### 2.9 版本与变更

- 契约草稿版本从 **v0.1（由公开基准自动生成）** 起；变更记录（附录 D）保留每次变化。
- 证据更新时：记录「旧结论失效 + 重算」，每项变化都带**依据**。
- 撤回 = 回到补前状态：**干净复原、无残留**（数字 / 状态 / 试点范围全回）。
- 项目层面：每阶段完成打「阶段标识」（记入《进度与变更记录》；有 Git 时用小步本地提交）。

## 3 · 规则（核心）

### 3.1 收益口径（两步式，数字全可复算）

- **第一步（物理量）**：**可释放工时**（工时/月）。
- **第二步（现金口径）**：**可减少现金支出**——**只有**工时可真正从固定成本变成可变成本时才成立；**「可释放工时 ≠ 可减少现金支出」必须同屏可见**。
- **金额叫法**：一律称「**假设情景下的潜在优化空间（用工结构口径）**」，不是「你正在漏的钱」，更不是承诺。
- **算法口径**：
  - 月总工时 = 门店数 × 单店员工数 × **174**（国家标准口径 21.75 天 × 8 小时）；人时营业额 = 总营业额 ÷ 月总工时；
  - 可释放工时的换算基数 = **当前全职占比（= 1 − 当前兼职占比）**；「拟调整占比」是试点目标，**不进公式**；
  - 公开基准：同一家店从全职排班改小时排班，当日总工时 **198 → 137**，即 **约 30.8%**（由两端点线性推导；**别人的店，不是本客户实测**）；
  - 小时成本取公开区间 **25–35 元/小时**；金额 = 可释放工时 × 12 × 小时成本（区间对区间）；
  - 兼职占比未确认 → 按 **10%–60% 扫描**并标 `ASSUMPTION`（公开数据缺口，需现场问）；已确认 → 按 ±15% 不确定带。
- **必须展示**：假设清单（198→137 出处、基数口径、25–35、174 国标）、适用条件清单（固定→可变、需实际数据收窄、服务质量约束、174 为估算应替换）、复算步骤（①…⑤ 客户可自己按计算器）。
- **不可相加**：「用工结构」与「人效交叉」两条诊断机制部分重叠，**不得相加**。
- 若客户明确说「固定工资不变、编制不动」：现金口径**不得**自动成立，仅展示工时物理量与条件（见《03》场景 7）。

### 3.2 停止建议规则（允许零收益）

- **客户陈述级**反向证据（「没有冗余 / 不存在多排 / 人手紧」类，未附数据）→ 候选 B =「**存在反向证据，需核实**」；验证动作=先核实；**核实前不推进该改造**。不得把一句话升级成「已实测」。
- **数据级**反向证据（内部数据支持「无可释放工时」）→ **允许计算结果为零并停止建议**：
  - 可释放工时 → **0**（展示「0」而非区间）；
  - 金额 → 「**已停止 —— 反向证据支持无可释放工时**」；
  - 原公开基准区间降级为「**独立假设模拟（不适用于本客户）**……仅作对照演示，不作为本客户的推荐收益」；
  - 复算列改为「**为什么停 / 如何重启**」，**不得出现 `0–0` 之类的残数**；
  - 候选 B =「数据支持无可释放工时 · 停止该改造建议」；试点范围切换为「排班解释与返工试点」。
- 重启路径：提供能推翻该反向证据的原始数据 → 按同一流程重新评估。

### 3.3 诚实性约束（贯穿全局）

- 状态只由条件计算；**模型不能升级状态、不能改数字、不能发明因果**。
- 模型只做两件事：① **结构化抽取**（带原句）；② **把算好的结论说成人话**。
- 占位符：**〔待填〕** = 现场手写位（打印后填写，空着是设计）；**〔未提供 · 待补〕** = 目前拿不到、需向甲方索取。
- 预跑 / 合成参与时，页面与契约附录**同时**标注，不得只标一处。

## 4 · 输入输出示例

**输入示例（合成聊天记录，可直接用作测试）**：

> 周主管：门店排班各家店长自己弄，至少一天。
> 李经理：之前用过什么工具吗？
> 周主管：去年买过一套排班系统，店长说看不懂它派的班，后来就没人用了。
> 周主管：12 家店，单店月流水差不多 30 万，一家店八个人。
> 王店长：还有个事，店员老担心以后工时被压。

**关键输出示例**：
- 抽取页一句话：「引用定位 N/N 条均可在原文定位；其中 X 条原句完整支持结论，Y 条只有部分支持（余下留作待验证推断）。」
- 提问页一句话：「材料已经回答了 X/Y 个问题；下面 Z 个是真的必须问的。」
- 报告页：状态条（如 ⏳ 待补证据 / 🧭 可设计试点）；候选 A、B 各自的状态与依据；金额行「假设情景下的潜在优化空间：**61.8 万 – 194.5 万元/年**（兼职占比未确认，按 10%–60% 扫描）」——具体数字以规则复算为准。
- 停止态：「该改造建议已停止（反向证据支持无可释放工时）；原基准区间仅作『独立假设模拟』对照。」+ 复算列「为什么停 / 如何重启」。
- 契约附录 F.3a 示例行：「已更正（替代关系）：旧值 8 人保留在历史；当前计算采用新值 10 人。」

## 5 · 验收标准

| # | 验收点 | 判定（要能判真假） |
|---|---|---|
| 1 | 回指校验 | 构造一条不在原文的 quote → 必须被降级并打标，且不计入「可定位」计数 |
| 2 | 更正 / 冲突 | 同人明确更正 → 替代关系、全链不再列冲突；异人矛盾 → 保留「待核实冲突」、不覆盖不平均 |
| 3 | 反向表述 | 「基本没有返工」类**不得**计入支持证据，且单独提示 |
| 4 | 证据门槛 | 缺基线 / 默认参数 → 停在「待补证据」；条件补齐才升级；写文案不能改变状态 |
| 5 | 双轨口径 | 「可释放工时 ≠ 可减少现金支出」与条件清单必须可见 |
| 6 | 零/停止 | 数据级反向证据 → 工时 0、金额「已停止」、原区间降级为独立假设模拟；无 `0–0` 残数 |
| 7 | 草案 / 导出 | 11 块齐全；下载与页面**逐条一致**；验收标准不出现「提升/优化/增强」；〔待填〕占位符在位 |
| 8 | 补证据 / 撤回 | 变化报告含「之前 / 之后 / 依据」；撤回后无残留 |
| 9 | 离线 / 预跑标注 | 加载预跑必须显示「演示模式 — 捕捉于 …」；契约附录同步标注 |
| 10 | 主流程 | 丢材料 → 导出 → 补证据 → 撤回，全链不中断、不编造、每步有下一步入口 |

**视觉项（人工，不参与自动验收）**：见《04》第 5 节（视觉检查；含两张参考截图的位置与检查清单）。

## 6 · 首版范围 / 非范围

**首版包含**：餐饮一条线端到端（上述 1–9 步）；至少「情景一」补充证据；离线演示；测试与变更记录。

**首版不包含（不要求实现）**：
1. 物流行业与跨行业切换；
2. 资产库（可复用沉淀）；
3. 情景二 / 情景三（可选加分项，不是必须）；
4. 多用户 / 账号 / 数据库 / 云部署；
5. 薪资核算、考勤机对接等超出演示范围的交付功能；
6. 视觉 / 美学的自动验收（永远人工）。

## 7 · 术语表

| 术语 | 含义 |
|---|---|
| 回指校验 | 模型给的每条原句，必须能在材料里逐字找到；找不到即降级 |
