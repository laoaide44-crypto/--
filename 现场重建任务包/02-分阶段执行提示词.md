# 02 · 分阶段执行提示词

> 用法：新建会话在**空目录**开工；**一次只给一段提示词**（可连同本文件与《01》一起提供）。每段做完 → 跑自测 → 对照《03》用例 → 按《04》存档 → 再给下一段。**不要一条提示词要求生成整个项目。**

---

## 通用纪律（每段都适用，提示词内会再次提醒）

**A.** 代码、算术、状态**由程序控制**；模型只做两件事：① 结构化抽取（必须带原句）；② 把算好的结论说成人话。**不许发明因果、不许新增数字。**
**B.** 每段**先检查上一段成果再继续**；不得覆盖 / 重写已验收模块（发现坏了先修，并说明修了什么）。
**C.** 依赖只允许 streamlit（固定版本）；新增任何依赖都必须说明必要性，并保持**离线可运行**。
**D.** **合成 / 预跑**内容必须如实标注；**密钥不进代码、不进日志、不进对话**。
**E.** 每段交付物 = 可运行行为 + 自测脚本 + 进度记录（格式见《04》）。
**F.** 失败要**如实显示、可定位**；不许静默吞错、不许假装运行。

## 建议的模块边界（职责必须清晰；文件名自定）

| 模块 | 职责 |
|---|---|
| 入口 / 页面 | 首屏、材料、抽取、提问、参数、报告、契约、补证据 |
| 内核 | 事实 / 候选 / 门槛 / 收益 / 契约的**统一数据结构** |
| 基准库 | 公开数字 + 出处 + 来源等级 |
| 抽取层 / 事实层 | 切分、遮蔽、扫描、模型抽取、回指校验、三层校验、更正 / 冲突 |
| 判断层 | 候选问题、反向证据、证据门槛 |
| 测算层 | 工时 / 金额两态（正常 / 停止） |
| 契约层 | 11 块 + 附录渲染与导出 |
| 证据层 | 情景解析、替换语义、变化报告、撤回 |
| 演示缓存 | 预跑保存 / 加载与标注 |
| 启动 / 测试 | 幂等启动脚本；逐段自测脚本 |

## 六段总览

| # | 阶段 | 一句话产出 |
|---|---|---|
| 1 | 项目骨架、依赖与最小可运行页面 | 能启动、能丢材料、能看到确定性扫描 |
| 2 | 统一事实记录、来源、明确更正和未解决冲突 | 事实带 ID/出处；更正与冲突分开 |
| 3 | 候选问题、反向证据与确定性证据门槛 | 问得准；判断保守；状态算出来 |
| 4 | 测算、条件与假设展示，支持零收益及停止建议 | 双轨口径；可归零、可停止 |
| 5 | 草案与导出，完整传递事实与状态 | 契约 11 块+附录；下载与页面一致 |
| 6 | 补证据、重算、撤回、离线演示和主流程验收 | 证据变→判断变；可撤回；离线可演 |

## 提示词 1 · 项目骨架、依赖与最小可运行页面

```text
你要在**当前空目录**中，从零实现「餐饮门店 · 交付契约台」——一个给做交付的人用的、以「可验收」为核心的单页 Web 应用。本段只做**骨架与最小可运行页面**；不要实现抽取、判断、测算、契约等后续功能。

【0 · 开工前检查（先做，再动手）】
- 确认目录为空（或只有你将要创建的文件）；
- 确认 Python 可用（≥3.10）、pip 可用；
- 选一个**空闲端口**（避开现有服务，例如不要用 8501），启动前用 netstat 探测；
- 把检查结果先说清楚，再开工。

【1 · 本阶段输入及依赖】
- 无前序阶段；
- 本机 Python 3.10+；依赖只允许 streamlit（固定版本）；
- 本阶段不依赖网络与模型。

【2 · 实现范围】
- 项目骨架 + `requirements.txt`（只含 streamlit）+ `.streamlit/config.toml`（主题色、toolbarMode=minimal、headless）；
- 启动脚本（**幂等**）：已在跑→只开浏览器；没在跑→起服务、等就绪、再开浏览器；端口参数化；写启动日志；健康检查 `/_stcore/health` 返回 ok；
- 首屏（hero）：产品定位文案（「给做交付的人」「可复算 / 标来源 / 缺证据不给承诺」三个可信点）+ 两个入口：「丢一份材料进来 →」与「用预跑结果（离线演示）」（后者可先禁用并注明"下一阶段接入"）；
- 材料页：大文本框 +「用示例材料」+「抽取事实 →」；点击后显示**确定性扫描摘要**（不依赖模型）：材料单元数（聊天记录格式按「时间+发言人」切分；否则按空行分段）、字符数、隐私遮蔽次数（手机号 / 身份证 / 银行卡）、金额 / 百分比 / 日期 token 清单（去重）；
- 为后续阶段预留清晰模块边界（见任务包《02》总表），但**不要写空实现**：没做的功能要么不出现，要么明确标"下一阶段接入"。

【3 · 要交付的可运行行为】
- 应用可启动、可打开、无报错；
- 首屏完整；两个入口按钮在位（预跑可禁用 + 提示）；
- 材料页：粘贴任意文本 → 点「抽取事实 →」→ 出现扫描摘要（数字自洽）；
- 重复启动不产生第二个实例；健康检查 ok；
- 无网络、无密钥时同样可运行。

【4 · 验收用例】
a) 全新环境：装依赖 → 启动 → 打开首页，健康检查 ok；
b) 粘贴一段合成聊天记录 → 点抽取 → 扫描摘要出现（单元数 / 金额 / 百分比计数自洽）；
c) 重复执行启动脚本 → 不新起第二个服务；
d) 无密钥环境 → b) 仍通过。

【5 · 完成条件】
- 用例 a–d 全部通过；
- 端口、启动方式、日志位置写入《进度与变更记录》；
- 自测脚本（至少覆盖 a–c）可一键运行。

【6 · 失败时的定位方法】
- 端口占用：`netstat -ano | findstr <端口>` 找 PID 处理；
- 找不到 streamlit：用全路径 `python -m pip install -r requirements.txt`（国内加清华源）；
- 中文乱码：`chcp 65001` + 设 `PYTHONIOENCODING=utf-8`；
- 改代码行为不变：Streamlit 热加载不重导模块——**重启服务**；
- 子页面报错：检查是否引用了尚未创建的模块。

【边界】不提前实现后续业务逻辑；不伪造演示数据；按钮不能点了没反应（要么禁用要么给提示）。完成后向操作者汇报：做了什么、验证结果、遗留什么。
```

## 提示词 2 · 统一事实记录、来源、明确更正和未解决冲突

```text
本轮把「丢材料 → 抽事实」接上模型（可选）与确定性兜底，产出**统一事实记录**；并把「明确更正」与「未解决冲突」分开。目标：追问、测算、契约从此引用**同一份数据**。

【0 · 开工前检查】
- 启动应用走一遍阶段 1 用例（材料 → 扫描摘要）；
- 运行阶段 1 自测脚本；不过先修，不要往下走。**不覆盖上一阶段成果**（坏了先修，并说明修了什么）。

【1 · 本阶段输入及依赖】
- 阶段 1 骨架；
- 模型配置（可选）：环境变量 / `.env.local`（占位符模板见《00》）；**没有也要能跑**——降级路径必须成立；
- 测试材料：《03-合成材料与测试预期.md》场景 8 / 9 / 3 / 10。

【2 · 实现范围】
- 抽取（可选模型）：系统提示要求「只输出一个 JSON；每条必须带 quote（逐字、≤60 字）；找不到原句就不写；不许推断材料没有的事实；confidence 三档」；输出结构 facts / people / timeline / conflicts / unknowns / prefill（参数预填+原句）；宽容解析（去代码块、取最外层花括号）；调用失败要返回**明确错误**，不吃掉；
- 回指校验（硬闸门）：归一化（全角→半角、去引号与空白）后逐字查找；失败 → 标「无法回指」并**降级为推断**；统计行「引用定位 N/N 条」；
- 三层校验（定位 / 支持 / 适用）**分开记录**；「部分支持」的余下部分记「未覆盖部分（待验证推断）」；
- 统一事实记录：稳定 ID（同一句话多次运行不变；撞号加后缀）、来源类型、状态、材料位置；把事实**确定性归位**到契约字段（谁在做 / 试过什么 / 谁抵触 / 现有口径 / 关键原话）——已给过的不再显示「未提供」；
- 更正 vs 冲突：
  · 同来源 + 明确更正表述 + 同一对象 →「✅ 已更正（替代关系）」：旧值留历史、**新值进当前计算**、不再列冲突；
  · 其余矛盾 →「⚠ 待核实冲突」：保留、不覆盖、不平均；注明「需在同一对象、同一时间、同一口径下当面核实」；
  · 「买过 / 采购过 + 没人用 / 闲置 / 看不懂」→「落地失败线索」（是经历，不是矛盾）；
  · 反例纪律：「因预算停用软件」**不得**写成「因不可解释而停用」；
- 降级路径：无模型 / 断网 / 失败 → 确定性扫描照常；抽取如实为空或部分，**不编造**；页面如实提示。

【3 · 要交付的可运行行为】
- 有模型：材料 → 抽取 → 事实表（ID / 类型 / 事实 / 原句 / 位置 / 来源 / 状态 / 原句支持 / 适用性）+ 统计行 + 「已更正」块 + 「待核实冲突」块 + 「落地失败线索」块；「用预跑结果」入口占位；
- 无模型：界面如实显示「未接入模型 / 仅确定性扫描」，不产生假事实、不崩溃。

【4 · 验收用例（《03》对应场景）】
- 场景 8（同人更正）：出「已更正（替代关系）」，「待核实冲突」0 条；旧值保留、新值进计算；
- 场景 9（异人冲突）：出「待核实冲突」，无「已更正」块；不得取平均或擅自采用；
- 场景 3（预算停用）：全页无「不可解释 / 看不懂」断言；无疑似冲突误报；
- 场景 10（部分支持）：计数区分「完整 / 部分」；部分支持不计入「完整支持」；
- 附加：人为构造一条原文里没有的 quote → 必须降级、「可定位」计数相应减少；同一句话跑两次 → ID 相同。

【5 · 完成条件】
- 上述用例全过（写成自测脚本，≥10 条断言）；
- 更新《进度与变更记录》。

【6 · 失败时的定位方法】
- quote 校验失败：打印「归一化 quote」与「材料片段」逐字符对比（全角 / 引号 / 空白差异）；
- 模型返回非 JSON：把原始输出记入日志，先查解析器；
- 乱码 / 模块不生效：同阶段 1 做法。

完成后向操作者汇报：做了什么、验证结果（用例逐条）、遗留什么。
```

## 提示词 3 · 候选问题、反向证据与确定性证据门槛

```text
本轮建立：公开基准库、提问计划（只问该问的）、参数来源三态、候选问题 A/B、反向证据分级、证据门槛（状态由条件算出）。目标：**问得准、判得保守、状态可复算**。

【0 · 开工前检查】
- 复跑阶段 2 用例（至少场景 8 / 9）；材料 → 事实显示正常。**不覆盖上一阶段成果**；坏了先修。

【1 · 本阶段输入及依赖】
- 阶段 2；
- 参数默认值：门店 12 / 单店月流水 30 万 / 单店 8 人；
- 本阶段建立基准库（下述）。

【2 · 实现范围】
- 公开基准库（每条带出处、等级=公开可查；至少）：
  · 人时营业额·优秀标杆 180 元/小时；疑似亏损线 100 元/小时；
  · 人均产值 27 万元/年（≈129 元/小时，作行业均值换算）；
  · 全职工排班当日总工时 198 → 小时排班 137（可释放约 30.8%，注明「线性推导」「别人的店」）；
  · 小时用工成本 25 / 30 / 35 元/小时；月工时口径 174 小时；
  · 兼职占比未确认时的扫描区间 10%–60%（标「自定假设」，注明公开数据缺口）。
- 提问计划（只问该问的）：
  · 话题库 ≥6 条：兼职占比（最高优先） / 现有判断口径 / 内部数据索取 / 谁在做+耗时 / 谁抵触 / 过去尝试；
  · 每条带：为什么问 / 答了改变什么 / 从哪拿 / 是否必须当面；
  · 「已回答」判定**保守**：只有强信号才算；
  · 输出：已答清单（带原句）+ 必问清单（按优先级）+ 缺口参数 + 汇总行「材料已经回答了 X/Y 个问题…」；
  · 选择与排序**全部确定性**，模型不参与。
- 参数表单（三个数）+ **来源三态**：材料预填 / 客户自报 / 默认假设（值=默认值 → 视为默认假设，宁可保守）；来源必须在界面上标注。
- 候选问题 A/B（不预设结论）：
  · A：关键词确定性归位；相反表述（「基本没有返工」等）**不进支持**且单独列出；
  · B：支持关键词；反向证据按来源分三级（客户陈述 < 内部数据支持 < 实际试点验证）：
    - 陈述级 →「存在反向证据，需核实」+ 验证动作=先核实；
    - 数据级 →「数据支持无可释放工时 · 停止该改造建议」（数值归零在阶段 4 落地）；
  · B 常规判断：只支持「不知道」→「证据不足 · 暂不建议」；有分时段数据支持 →「需客户数据验证」；
  · B 的说明文必须含：「人时营业额高于标杆只说明人效不低，不能反推结构性漏损」「198→137 是别人的店，不是本客户实测」。
- 证据门槛：五条件（材料 / 客户给的参数 / 覆盖 / 基线 / 口径对齐）→ 四状态（待补证据 → 可设计试点 → 待验收实测 → 已完成试点验证）；can / cannot 文案；「收到材料 ≠ 证据充分」；**客户批准是独立开关，永不自置**。
- 「一次只问一件事」（简版）：按必问清单逐题；回答 → 现场访谈事实（无原句也保留，来源=现场访谈）；可跳过、可返回。

【3 · 要交付的可运行行为】
- 抽取页下方出现候选问题与门槛状态；参数页可改三个数、来源标注正确；提问页出现计划清单；
- 门槛状态随条件变化而更新（仍全部由条件计算）。

【4 · 验收用例】
- 《03》场景 5（陈述级反向证据 →「需核实」）；场景 4（反向表述不进支持 + 否定后「已被客户否定」）；场景 2（缺数：默认不当事实、门槛停在「待补证据」）；
- 同样输入跑两次 → 提问计划一致；补齐参数 → 门槛按条件升级；
- 「一次只问一件事」：答一题 → 生成一条现场访谈事实；「跳过」不阻断流程。

【5 · 完成条件】
- 候选状态由规则给出且可复算；门槛可复算；提问计划稳定；自测脚本过；更新记录。

【6 · 失败时的定位方法】
- 状态不稳定 → 查是否混入模型输出；反向证据误升级 → 查来源分级条件；缺口清单错 → 查默认值对比逻辑。

完成后向操作者汇报：做了什么、验证结果（用例逐条）、遗留什么。
```

## 提示词 4 · 测算、条件与假设展示，支持零收益及停止建议

```text
本轮实现收益测算（工时段 + 现金段）、假设与条件展示、复算步骤；并支持「零收益」与「停止建议」两种诚实输出。算术全部由程序控制。

【0 · 开工前检查】
- 复跑阶段 3 用例；参数 / 门槛行为正常。**不覆盖上一阶段成果**；坏了先修。

【1 · 本阶段输入及依赖】
- 阶段 3（参数 / 事实 / 标志 / 门槛）；基准库。

【2 · 实现范围】
- 计算（口径与《01》3.1 一致；不许模型参与）：月总工时=店数×人数×174；人时营业额=总流水÷月总工时；可释放工时=月总工时×30.8%×当前全职占比（=1−兼职占比）；金额=可释放工时×12×小时成本（25–35），出低 / 中 / 高；
- 展示：指标卡；金额块标题「假设情景下的潜在优化空间（用工结构口径）」；**两步式**（① 可释放工时=物理量 ② 可减少现金支出=需条件成立），「**可释放工时 ≠ 可减少现金支出**」必须同屏；假设清单；适用条件清单；复算步骤①–⑤（客户可自己按计算器重算）；
```
