# 04 · 现场执行与故障备选

> 适用对象：执行重建的人 / 会话 + 现场演示的人。原则：**不改现有成品、不占它端口、不留假记录、一切如实标注。**

---

## 1 · 每阶段：启动、检查、保存（固定动作）

**启动（每阶段完成后都要能一键复现）**
- 启动脚本（幂等）：已在跑 → 只开浏览器；没在跑 → 起服务、等就绪、再开浏览器；
- 健康检查：`http://127.0.0.1:<端口>/_stcore/health` 返回 `ok`；
- 端口选**空闲端口**（避开现有服务，例如冻结版用的 8501）；启动前 `netstat -ano | findstr <端口>` 探测；
- 日志写在项目目录内（如 `启动日志.txt`），出问题先看日志。

**检查（对照当段验收用例）**
1. 运行本阶段自测脚本（上一段的自测也要复跑一遍，防回归）；
2. 打开页面，按《03》对应场景手动走一遍；
3. 浏览器控制台无报错；
4. 结果记入《进度与变更记录》。

**保存（每阶段结束必做）**
- 更新《进度与变更记录》（模板见下）；
- **存在 Git 时**：小步本地提交，例如 `git add -A` + `git commit -m "阶段N: <一句话>"`；**不自动推送**、不改写历史；
- 没有 Git：至少保留《进度与变更记录》+ 每阶段一次的目录副本（命名带阶段与时间）。

**《进度与变更记录.md》模板**

| 时间 | 阶段 | 完成内容 | 验证结果（用例逐条） | 遗留 / 风险 | 端口 / 备注 |
|---|---|---|---|---|---|
| … | 阶段 N | … | … | … | … |

底部固定两节：
- **待人工确认**：赛事与评审口径 / 现场时长 / 环境条件（三个问题，见本文件第 7 节）；
- **已知偏差**：如与规格不一致处，如实列，不藏。

## 2 · 实时模型失败时：切到「明确标注的预跑演示」

**判定**：抽取等待过久（>60 秒）、报错、或结果为空 → 不硬等、不狂点。

**切换路径（两条，界面都要有）**
1. 抽取页：「**改用「预跑结果」继续演示 →**」；
2. 或从材料页选「**用预跑结果（离线演示）**」→「载入这份预跑结果 →」。

**切换后的纪律（必须做到）**
- 页面出现「**演示模式 — 捕捉于 <时间>**」警示条时，**照读该标注**，说明这是**之前联网跑过的结果，不是现在现算的**；
- 契约附录同步带「演示模式」说明（不得只标一处）；
- 预跑缓存按行业分开存放；不得把预跑结果描述成实时生成。

**断网 / 无密钥**：同样走上述路径；其余环节（回指校验、测算、契约、变化报告）离线全部可用。

## 3 · 时间不足时的取舍（保序）

**必须保留（P0，缺一不可）**
1. 启动 + 健康检查 + 独立端口；
2. 材料 → 抽取 → 回指校验（失败降级不造假）；
3. 统一事实记录（稳定 ID、三层校验）+ 更正 / 冲突分开；
4. 候选问题 A/B + 反向证据（至少陈述级）+ 证据门槛状态；
5. 三个数 + 金额双轨展示 + 复算步骤；
6. 契约草稿 + 导出（页面 / 下载一致）；
7. 补证据（情景一）→ 变化报告（含依据）→ 撤回；
8. 合成 / 预跑标注；
9. 主流程演示可走通。

**可以延后（P1，按剩余时间做）**
- 提问计划的话题库完整度（先保「缺口参数 + 保守跳过」）；
- 「一次只问一件事」的完整问答（可先只做清单 + 跳过）；
- 情景二 / 情景三；
- 内置示例材料的丰富度（先用《03》场景一的合成材料）；
- 测试脚本从「主路径」扩到「全量」；
- 离线预跑缓存的多余份数（至少保住餐饮一份）。

**可以不做的（P2）**
- 视觉打磨、动效、主题美化；
- 任何与物流 / 资产库相关的功能（首版明确不含）；
- 多浏览器兼容、移动端适配。

## 4 · 红线（全流程）

1. **不改动当前运行中的版本**（冻结版 / 现有服务一律不碰）；重建只在**新的空目录**里进行。
2. **不占用现有服务端口**；不启动 / 停止 / 重启现有服务；不杀别人的进程。
3. **不读取、不复制真实密钥**；密钥只在本机环境中。
4. **不伪造开发时间**（不虚构耗时、提交时间、截图时间）。
5. **不把复制或预跑成果描述成「现场原创」或「实时生成」**；用了什么就标注什么。
6. 不声称视觉已验收。

- [ ] 按钮是否被长内容淹没、是否可点可达；

## 6 · 常见故障速查

| 现象 | 处理 |
|---|---|
| 端口被占用 / 起不来 | `netstat -ano \| findstr <端口>` 找到占用，换空闲端口；**不要**杀现有服务 |
| 页面打不开 | 看启动日志；确认健康检查；重启本重建版服务 |
| 抽取为空 / 超时 | 走第 2 节切换路径（预跑），并如实标注 |
| 控制台中文乱码 | `chcp 65001` + `PYTHONIOENCODING=utf-8` |
| 改了代码行为不变 | Streamlit 不热重载已导入模块 → **重启服务** |
| 下载与页面不一致 | 统一渲染入口；见《02》阶段 5「失败定位」 |
| 撤回后仍有残留数字 / 状态 | 对照《02》阶段 6「失败定位」清理范围 |
| 断网 | 全流程仍可走：预跑 + 确定性扫描；抽取前直接选预跑入口 |

## 7 · 待人工确认（开工前问清）

1. **赛事与评审口径（2026-09-29 更新）**：已收到赛务关于「既有成果声明与评审核验」的回复——①赛前成果经 `PRE_EXISTING.md` 声明；②评审需现场新增开发说明 + 可运行 Demo / 部署说明；③私有仓库向授权专家临时只读、评审后关闭。**仍未明确**：`PRE_EXISTING.md` 提交入口 / 时间 / 是否需提前审核；授权专家账号、仓库平台与访问时段。**回复未涉及**材料复用边界（赛前材料能否进场、联网 / 模型 API、「现场生成」界定）——仍按「不得假设允许」执行，必要时向赛务追问。
2. **现场时长**：可用总时长、是否分段；演示时段安排。时间会决定第 3 节取舍清单的执行深度。
3. **环境条件**：机器是否可装 Python / Streamlit；网络与代理情况；模型密钥如何提供（只经本机环境，不进对话）；可用端口范围；浏览器与缩放（演示前调到 100%）。
