## 一句话

企业丢一堆乱材料进来 → 抽出**带出处、带来源等级**的事实(**回指校验**兜底)→ 只问该问的
→ 用**公开基准**算出一年在漏多少钱(**算术全摊开**)→ 出一份**能签字的交付契约**
→ 把经验**沉淀成可复用资产**。

**当前行业**:快递物流(主场景)/ 餐饮门店(对照组)。**换行业不改契约、不改界面。**

---

## 架构(三个铁律)

```
fde_kernel.py        通用形状:Case / Metric / Evidence / Input / money   ← 内核
      ↑
fde_ind_logistics.py 物流:单票差额 × 年件量      ┐ 算法完全不同,
fde_ind_catering.py  餐饮:工时冗余 × 小时成本    ┘ 却产出同一个 Case
      ↓
fde_contract.py      只认 Case,零行业逻辑
fde_registry.py      行业注册表 —— 「加一个行业」的唯一入口
app.py               表单由 INPUTS 生成,第一屏从 case 渲染;外壳文案由行业模块自带
```

1. **行业模块只读自己的基准**(`INDUSTRIES[自己]`),绝不读全局 `BENCH`
2. **行业模块不依赖界面当前选了什么**
3. **界面外壳(示例材料 / 追问清单 / 预填参数 / 讨数据那句 / 离线缓存)也由行业模块自带**

**加一个行业 = 4 处改动**(新建 `fde_ind_*.py` → `fde_bench` 两行 → `fde_registry` 两行 → 跑 `test_shell.py` 自查),
完整清单与时间预算见 `文档/12-新增行业的操作手册.md`。

## 改代码前请注意(都是踩过的坑)

1. **改完被 Streamlit 导入的 `fde_*.py` 必须重启服务** —— 热加载不会重新导入已缓存的模块
2. **同一文件里不要重复定义同名函数** —— 后面的会静默覆盖前面的
3. **行业闸门不可绕过**:选了"只有数据、没有模型"的行业要**明确停住**,
   绝不能拿别的行业的公式硬算(`fde_registry.get()` 返回 None 时 `st.stop()`)
4. **模型只许做两件事**:抽事实、把算好的结论说成人话。**不许发明因果,不许新增数字**
5. 密钥只放 `.env.local`(已 gitignore),**任何情况下不打印、不打包、不进对话**

完整的踩坑记录:`文档/09-技术实现与踩坑记录.md`。
