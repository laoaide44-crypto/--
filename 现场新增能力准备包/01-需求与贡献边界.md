## 0 · 边界口径（先读）

1. **本轮只准备文档与合成样本**：不实现功能、不生成应用代码、不安装依赖、不修改当前产品或冻结快照、不启动服务、不调用模型 API。
2. **不把已有功能算成新增**：现有「上传文件」入口**已经能读入含 `csv` 后缀的文件**，但它把文件**当作纯文本材料**交给抽取流程（`fde_intake`），**不做结构化解析、不校验字段、不计算工时**。因此本轮新增的是「**结构化 CSV 排班表**」这条能力，**不是**「能不能上传文件」。
3. **现场工作一律标注「计划 / 尚未实施」**；本包任何数字、结论都不构成「已实现 / 已验收」。
4. **严格边界（贯穿全包，不得放宽）**：
   - 排班表 = **计划安排**，**不等于**实际出勤、实际工作、工资支付；
   - **文件导入 ≠ 真实性已验证**；
   - 没有客流 / 岗位需求 / 服务质量 / 薪酬数据，**不得**认定冗余、合理编制或现金节省；
   - **合成数据不得升级为真实客户证据或真实试点结果**；
   - 本轮及现场首版**只支持 CSV**——不扩展 Excel、OCR、自动排班、多行业、聊天功能。

## 1 · 目标用户与使用时机

| 项 | 内容 |
|---|---|
| 目标用户 | 做交付的人：咨询顾问 / 现场交付工程师（与现有产品同一用户） |
| 使用时机 | **访谈拿到排班表之后、写方案之前**——手里第一次有了「门店自己排的计划表」这种**结构化原始数据** |
| 触发场景 | 客户/店长发来一份排班 CSV；此前产品只能把它的文本倒进抽取，**无法核对字段、无法定位到具体行、无法算表内工时、无法和自报数字比口径** |
| 本次要解决的核心痛点 | 让**表格数据约束判断**：先算清楚「表里到底排了多少计划工时」，再和此前的自报/假设比；**而不是**一有数据就生成一个更大的收益数字 |
| 核心价值一句话 | **让表格数据约束判断，而不是直接生成更大的收益数字。** |

## 3 · 用户流程（选择入口 → 校验 → 预览/草稿 → 确认应用 → 查看变化 → 撤回）

| 步 | 用户动作 | 产品做什么（确定性） | 标注与纪律 |
|---|---|---|---|
| 1 | 在**现有上传入口**选「**作为文本分析**」/「**作为排班表校验**」（排班表仅 `.csv`、UTF-8） | 「文本分析」→ 走既有抽取；「排班表校验」→ **确定性解析与校验**，**不把整份文件自动发给模型** | 显示「文件导入 ≠ 已核实」 |
| 2 | 看校验结果 | 逐行 / 逐字段检查；**阻断错误**列出行号 + 字段 + 原因；**提示性问题**单列；写**校验状态**（待校验 / 有阻断问题 / 结构校验通过） | 阻断行**不参与计算** |
| 3 | 看预览与工时 | 无阻断、无未解决重叠 → 给「**文件内已解析记录工时合计**」（并列声明范围 / 实含范围 / **完整性是否已确认**）；否则只给「**无异常记录小计**」；可存**待处理草稿** | **取消「区间并集」**；重叠列为**未解决冲突**；**合计 ≠ 范围完整** |
| 4 | 填/确认本次数据范围 | 分别记录**用户声明范围**、**文件实际包含范围**（门店、起止日期、人员数）与**完整性是否已确认**；**没记录的日期 / 门店不按零** | 不得仅凭日期连续认定「数据完整」 |
| 5 | 与基线 / 自报 / 假设对照 | 四维可比性（门店 / 日期 / 人员 / 工时定义）；一致 → 给差异，且**只有范围与口径一致才可比较或替换对应部分**；不一致 → 明示「不可直接比较」 | 自报与假设**保留历史**，不被静默覆盖 |
| 6 | **用户确认**后应用 | **一次确认应用 = 一个证据版本**；记录文件哈希 / 规则版本 / 声明与实含范围 / 来源与标注 / 结果及前版引用；触发判断与草案**同一计算链重算** | 确认是显式动作；模型不得代为确认或决定升级；**确认前用户须能看见去重处理结果** |
| 7 | 查看变化 | 变化报告：**之前 / 之后 / 依据**（沿用 A9 结构）；受影响判断、试点范围、草案逐条列出 | 旧结论失效需显式标注 |
| 8 | 切换版本 / 撤回 | 门店 / 日期筛选是**版本内视图**；撤回只恢复**上一版本及其派生结果**，**不抹去历史** | 撤回后计数归零 |

## 4 · 最小范围与明确「不做」

### 最小范围（首版必须成立）

1. 在**现有上传入口**内增加**显式选择**：作为文本分析 / 作为排班表校验（上传入口复用，**不计新增**）；
2. 只接受 **CSV**（UTF-8，可容忍 BOM）；结构化路径**不自动把整份文件发给模型**；
3. 只认 **5 个必需列**（见《02》）：门店标识 / 员工匿名标识 / 班次开始 / 班次结束 / 不计入工时的休息分钟数；
4. 校验分级：**阻断错误** vs **提示性问题**；记录**校验状态**（待校验 / 有阻断问题 / 结构校验通过）；
5. 表内计划工时**确定性计算**（分钟为单位；`工时 = 结束 - 开始 - 休息`）；无阻断、无未解决重叠 → 给「**文件内已解析记录工时合计**」（并列声明范围 / 实含范围 / 完整性是否已确认）；否则只给「**无异常记录小计**」；
6. **合计 ≠ 范围完整**：不得称为「客户全部工时」，不得替换更大范围的基线；存在阻断或未解决重叠 → **不得**应用为完整基线；允许存**待处理草稿**，修正后重新校验再确认应用；
7. 四维口径可比性检查（**仅范围与口径一致时才可比较或替换对应部分**）；
8. **一次确认应用 = 一个证据版本**；判断 / 草案重算；撤回只恢复**上一版本及其派生结果**；
9. **合成样本始终带演示标识**（文件名 `SYNTHETIC_` + 页面标注）；
10. **完全重复**按已声明规则去重、计一次、保留原始行号映射、显示去重数量及对工时的影响（属**已处理的数据质量提示**）；**确认应用前用户须能看见去重处理结果**。

### 明确不做（本轮与现场首版都不做）

| 不做 | 原因 |
|---|---|
| Excel / xlsx / OCR / 图片排班表 | 首版只支持 CSV，控制校验面 |
| 自动排班 / 排班建议 | 越出「校验 + 计算 + 证据」范围 |
| 多行业 / 聊天 / 多语言 | 首版单场景 |
| 工资核算、出勤认定、支付认定 | 排班表 ≠ 实际出勤 ≠ 工资支付 |
| 判断「冗余 / 合理编制 / 现金节省」 | 缺客流、岗位需求、服务质量、薪酬数据 |
| 设定法律或行业阈值（如「超 8 小时违法」） | 不随意设定阈值；只做**格式与内部一致性**校验 |
| 把一周结果外推全年 | 不外推 |
| 使用真实客户数据 | 只用虚构门店与匿名员工 |
| 让模型做算术或决定证据升级 | 解析/校验/计算/版本一律确定性代码 |
| 在结构化路径把整份文件自动发给模型 | 结构化路径先做确定性解析与校验（入口处由用户选择） |
| 用「区间并集」消解重叠、或用重叠自动生成合计 | 重叠可能是录入错误 / 重复安排 / 跨店支援等**待确认情况**；且 `break_minutes` 只有总量、没有发生时间，**无法准确计算净工时并集** |
| 把「文件内已解析记录工时合计」当作客户全部工时或更大范围的基线 | 算术合计有效 ≠ 范围完整；不得称为「客户全部工时」，不得替换更大范围基线 |
| 把没记录的日期 / 门店按零工时处理 | 缺记录 ≠ 零；不自动补零 |
| 撤回时抹去历史版本 | 撤回只恢复**上一证据版本及其派生结果** |
