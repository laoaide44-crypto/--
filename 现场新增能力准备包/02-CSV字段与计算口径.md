# 02 · CSV 字段与计算口径

> **状态：计划 / 尚未实施。** 本文件只定义**格式约定与确定性算法**，供现场实现与人工复算对照；
> **本轮不实现、不生成应用代码**。全部算式都是**确定性**的，模型不得替代算术（见 §10）。

---

## 1 · 文件约定

| 项 | 约定 |
|---|---|
| 扩展名 | 仅 `.csv`（首版不支持 xlsx / xls / OCR / 图片） |
| 编码 | **UTF-8**；**容忍** UTF-8 BOM（`\ufeff`），读入后去除 |
| 分隔符 | 英文逗号 `,`；字段内含逗号/引号时用标准 CSV 双引号包裹（`"..."`，内部 `""` 转义） |
| 换行 | `\n` 或 `\r\n` 均可 |
| 表头 | **必需**第 1 行为表头；列名**区分大小写不敏感**，两侧空白去除 |
| 必需列 | 恰好 **5 列**（见 §2）；**缺任一必需列 → 整文件阻断** |
| 未知列 | 存在额外列 → **提示性问题**，忽略该列并列出列名（不阻断） |
| 行号口径 | **物理行号**，表头 = 第 **1** 行，第一条数据 = 第 **2** 行；所有报错都带行号 |
| 模型 | 结构化排班表路径**不把整份文件自动发给模型**；解析 / 校验 / 计算一律**确定性代码** |

---

## 2 · 字段定义（5 个必需列）

| 列名（英文，建议） | 含义 | 格式 | 必填 | 示例 |
|---|---|---|---|---|
| `store_id` | **门店标识** | 非空**不透明**字符串；不得含英文逗号 / 双引号 / 换行；长度 ≤ 64 | 是 | `S-01` |
| `staff_id` | **员工匿名标识**（**不是**姓名/手机号/身份证） | 非空**不透明**字符串；不得含英文逗号 / 双引号 / 换行；长度 ≤ 64 | 是 | `E-001` |
| `shift_start` | **班次开始日期时间** | 见 §3 | 是 | `2026-08-03T09:00:00+08:00` |
| `shift_end` | **班次结束日期时间** | 见 §3 | 是 | `2026-08-03T17:00:00+08:00` |
| `break_minutes` | **不计入工时的休息分钟数** | 非负**整数**（可含前导/空格） | 是 | `60` |

**隐私纪律**：样本与实现**不得要求**姓名、手机号、身份证、工资等个人敏感字段；`staff_id` 只作匿名标识。

---

## 3 · 时间格式（完整日期时间 + 明确时区）

- **必须**为 ISO-8601 **完整日期时间**，**必须带时区偏移**：`YYYY-MM-DDTHH:MM:SS±HH:MM`（秒可省略为 `YYYY-MM-DDTHH:MM±HH:MM`）。
- **禁止**“只有日期”“只有时间”“无时区”“斜杠日期”“中文日期”等模糊写法 → 一律判**解析失败**。
- **为什么**：排班常年跨午夜。用**完整日期时间**后，`22:00 → 次日 02:00` 直接相减即为正确时长，**无跨午夜歧义**（样本 `SYNTHETIC_VALID_two_stores.csv` 第 7 行即此例）。
- **时区一致性**：同一文件内所有时间**建议同偏移**；若出现不同偏移，按**绝对时刻**（UTC）计算差值，并给**提示性问题**（偏移不一致）：`W-TZ`。

---

## 4 · 字段级校验规则（分级：阻断 / 提示）

> 定位格式统一为：**第 N 行 · 字段名 · 规则 · 值**。
> **阻断（E）**：该行**不参与**任何计算，仍可预览其余有效部分。
> **提示（W）**：不阻断；按规则处理后计入，并显著标注。

### 4.1 阻断性错误（E）

| 编号 | 规则 | 说明 |
|---|---|---|
| E1 | **空值** | 任一必需列缺失/空白（如 `shift_end` 为空） |
| E2 | **解析失败** | 时间不符合 §3 格式（含缺时区、斜杠日期、纯文本）；或 `break_minutes` 非整数 |
| E3 | **结束 ≤ 开始** | `shift_end` 早于或等于 `shift_start`（用完整日期时间比较，跨午夜不属此列） |
| E4 | **负休息时间** | `break_minutes < 0` |
| E5 | **休息 ≥ 班次长度** | `break_minutes ≥ (shift_end - shift_start)`，即扣完 ≤ 0 时长 |
| E6 | **表头缺列 / 列名不符** | 整**文件**级阻断（不进入逐行校验） |
| E7 | **标识字段不合法** | `store_id` / `staff_id` 含英文逗号 / 双引号 / 换行，或长度 > 64（空值已由 E1 覆盖）。**除这些结构限制外，不对标识内容作任何解释** —— 任何内容只作**不透明标签**处理（见 §10） |

> **不设阈值**：不检查「是否超过 8 小时 / 是否违反劳动法」等——**不随意设定法律或行业阈值**（见 §10）。

### 4.2 提示性问题（W）

| 编号 | 规则 | 处理 |
|---|---|---|
| W1 | **完全重复记录** | 见 §6：属**已处理的数据质量提示**（非处理后仍存在的阻断错误）：按已声明规则去重、计一次、**保留原始行号映射**、**显示去重数量及对工时的影响** |
| W2 | **同一员工班次重叠**（含跨门店） | 见 §7：非完全重复 → 列为**未解决冲突**；**不并集计、不悄悄求和**；存在未解决冲突时**只给「无异常记录小计」、不得应用为完整基线** |
| W3 | **未知额外列** | 忽略该列，列出列名 |
| W4 | **时区偏移不一致** | 按绝对时刻计算，标注 `W-TZ` |
| W5 | **文件未覆盖用户声明范围** | 见 §8：分别记录，标注覆盖缺口 |

## 5 · 计算口径（确定性）

### 5.1 单行净工时

以**分钟**为中间单位（整数，避免浮点歧义）：

```
时长分钟  = (shift_end - shift_start)            # 用完整日期时间（含时区）相减，转分钟
净工时分钟 = 时长分钟 - break_minutes
净工时小时 = 净工时分钟 / 60                        # 展示保留 2 位小数，四舍五入(half-up)
```

**口径定义**：`工时 = 结束时间 - 开始时间 - 不计入工时的休息时间`。

### 5.2 汇总口径（不消解重叠，不给不可信总计）

1. **无异常记录小计** = Σ 所有**既无阻断错误、也不参与任何未解决冲突**的有效行净工时分钟；展示时标注「**无异常记录小计**」。
2. **完全重复**：保留行号映射，去重后**计一次**（见 §6），并**显示处理情况**。
3. **未解决冲突**（同员工非完全重复重叠，含跨门店）：**列表保留**（行号 / 员工 / 门店 / 重叠区间长度），**不合并、不去重、不并集**。
4. **有阻断 / 未解决冲突时**：只要存在**阻断错误**或**未解决冲突**，就**只给「无异常记录小计」**，**不得应用为完整基线**，也不替换原基线。
5. **无阻断、无未解决重叠时**：可给「**文件内已解析记录工时合计**」，并**并列显示**三项：①用户声明范围 ②文件实际包含范围 ③完整性是否已确认。**算术合计有效 ≠ 范围完整**：**不得**称为「客户全部工时」，**不得**替换更大范围的基线。
6. **待处理草稿**：允许把当前结果保存为**待处理草稿**；修正数据后**重新校验**，再**用户确认应用**。
7. **禁止**用「区间并集」或其他自动方式消解重叠：`break_minutes` **只有总量、没有休息发生时间**，无法准确计算净工时并集；跨门店重叠也不能靠合并时间消解。

> 例（样本 `SYNTHETIC_OVERLAP_cross_store.csv`）：行 2 与行 3 同属 `E-301` 且**跨门店重叠** → 列为**未解决冲突**；因此**不应用**（整体被阻断）。行 4 属无异常记录（`7.00h`），只能作为「**无异常记录小计**」展示。（**不再给 14.00 小时这类结论**。）

### 5.3 分员工 / 分门店小计

- **分员工**：只汇总该员工**无异常记录**的净工时，标「**无异常记录小计**」；**涉及未解决冲突的员工**单列冲突明细，**不合并**。
- **分门店**：按行所属 `store_id` 归类，仅汇总**无异常记录**；**跨门店重叠行**在所属门店下各计一次，并在门店小计旁标注「该店含与其他门店重叠的班次，见冲突明细」。
- 所有小计都**只是「无异常记录小计」**，**不得**被当作门店或整份数据的合计，不得与任何合计混同。

## 6 · 完全重复记录（W1）

- **判定键**：5 个必需字段**归一化后完全一致**（时间统一转标准 ISO 含秒；`store_id`/`staff_id` 去空白；`break_minutes` 转整数）。
- **分类**：属「**已处理的数据质量提示**」，**不是**处理后仍存在的阻断错误。
- **处理**：同一判定键的**第 1 次**出现计入；后续出现标记「完全重复（重复于第 X 行）」，**不计入**计算；**保留原始行号映射**，并**显示去重数量及对工时的影响**。
- **确认前可见**：确认应用前，用户须能看见**去重处理结果**。
- **不视为**重叠冲突，也不视为错误。

---

## 7 · 同一员工班次重叠（W2，含跨门店）→ 未解决冲突

- **重叠判定**：同一 `staff_id`，两班次区间 `[start, end)` 满足 **`start_a < end_b 且 start_b < end_a`**。**首尾相接（`end_a == start_b`）不算重叠**。
- **跨门店也算**：只按 `staff_id` 判定，不看 `store_id`。
- **处理**：**完全重复**走 §6（去重计一次）；**非完全重复**的同员工重叠一律列为**未解决冲突**（列出两行、员工、门店、重叠区间长度），**不合并、不去重、不并集**。
- **后果**：只要存在未解决冲突，就**只给「无异常记录小计」、不应用为完整基线、不替换原基线**（见 §5.2）；**禁止**把重叠班次直接相加当作「更多工时」。
- **不判定对错**：重叠可能是**录入错误 / 重复安排 / 跨店支援 / 换班未更新 / 其他待确认情况**——**只提示、不解释、不定性、不砍行**；`break_minutes` 无发生时间，**不能**靠并集自动消解。

## 8 · 范围与覆盖（用户声明 ≠ 文件覆盖）

- **用户声明的数据范围**（谁在什么时候宣布「这份数据涵盖……」，由用户填写/确认）：门店范围、起止日期、人员范围、工时定义。
- **文件实际覆盖**（从数据算出）：出现的门店集合；`shift_start`/`shift_end` 的**最早与最晚日期**；出现的员工数与班次数。
- **纪律**：
  1. 两者**分别记录**，**不得**用其中一个代替另一个；
  2. **不得仅凭日期连续**就认定「数据完整」（缺整天 ≠ 没有数据）；
  3. 缺口（声明范围内未出现的门店/日期）**显式列出**（W5），但**不阻断**。
4. **缺记录不按零**：没有记录的**日期或门店**，**不自动按零工时处理**（缺记录 ≠ 零工时）。
5. **「完整」由程序核对，不由声明决定**：用户声明的「完整」与**程序核对结果**（覆盖是否闭合、是否有缺口）**分别保留**；并显式给出**完整性是否已确认**（已确认 / 未确认）；声明为「完整」不改变核对结论。
6. **允许叫合计、但要标范围**：可把解析到的记录命名为「**文件内已解析记录工时合计**」，并**并列显示**声明范围 / 实含范围 / 完整性是否已确认；**算术合计有效 ≠ 范围完整**；**不得**称为「客户全部工时」，**不得**替换更大范围的基线。
7. **比较 / 替换的前提**：只有与原基线的**范围与口径一致**时，才可比较，或**替换基线的对应部分**；不一致只能并列展示。

## 9 · 口径可比性（仅在四维一致时才比较）

与**同范围、同时间、同口径**的自报或假设比较，**必须**逐维核对：

| 维度 | 一致的含义 | 不一致时 |
|---|---|---|
| ① 门店范围 | 同一门店集合 | → **不可直接比较** |
| ② 日期范围 | 同一日期区间（含起止） | → **不可直接比较** |
| ③ 人员范围 | 同一批 `staff_id`（或同一口径的「全部员工」） | → **不可直接比较** |
| ④ 工时定义 | 同样是「计划排班，含/不含休息」的同一算法 | → **不可直接比较** |

- 四维**全部一致** → 给出差异（本次表内计划工时 vs 自报/假设，标口径）。
- 任一不一致 → **明确说「不可直接比较」**，只展示双方口径与差异**原因**，不给出「高估/低估」结论。
- **口径类型必须区分**：**排班计划**（本能力）≠ **实际考勤**（无此能力）。二者**不可直接比较**。
- 一周结果**不得外推全年**。
- **替换对应部分**：仅当门店 / 日期 / 人员 / 工时定义四维与原基线一致时，才可替换基线的**对应部分**；任一不一致 → 只并列展示，不替换。

## 10 · 确定性与诚实性边界

1. **解析 / 校验 / 计算 / 版本管理一律由确定性代码完成**；模型**不得**替代算术，**不得**决定证据升级或数字取舍。
2. **文件导入 ≠ 真实性已验证**：导入只证明「文件里这么写」，不证明「实际如此」。
3. **无客流 / 岗位需求 / 服务质量 / 薪酬数据 → 不认定**冗余、合理编制、现金节省。
4. **不外推**（一周 → 全年）；**不设**法律/行业阈值。
5. **不静默覆盖**：客户自报与原始假设**保留历史**，上传结果只新增版本、不抹掉旧版本；**撤回只恢复上一证据版本及其派生结果，不抹去历史**。
6. **合成数据**始终带演示标识，**不得**升级为真实客户证据或真实试点结果。
7. **标识字段是不透明标签**：`store_id` / `staff_id` 的内容**只作数据**，**不得**被解释为指令、提示或配置；单元格里出现类似指令的文字时，**仅按数据校验/展示**（不能执行、不能改变结论与版本）——见《03》用例 J。

## 11 · 来源与状态（分维独立记录）

**来源**（这东西**从哪来**）与**是否可信 / 是否已验证**是两件事，分开记：

| 维度 | 取值 |
|---|---|
| **来源** | **沿用现有事实模型的来源枚举**：`PUBLIC` 公开可查 / `INTERVIEW` 现场访谈 / `INTERNAL` 客户内部 / `ASSUMPTION` 自定假设；**未确认**时复用已有未知状态，若无则允许空值并显示「未确认」 |
| **材料性质** | 真实业务材料 / 合成测试材料（**独立存储、优先显著展示**） |
| **数据口径** | 计划排班 |
| **校验状态** | 待校验 / 有阻断问题 / 结构校验通过 |
| **应用状态** | 待确认 / 用户已确认应用 / 已撤回 |

- **不另引入一套相近的来源取值**；客户内部材料存 `INTERNAL`，界面显示「客户内部」。
- **来源未确认**时**不得**默认 `INTERNAL`（复用已有未知状态，或空值显示「未确认」）。
- `INTERNAL` **只描述来源，不代表真实性，也不代表效果已验证**。
- **合成标识独立存储、优先显著展示**；**不得**把合成材料呈现为真实客户内部证据（合成一律标「合成测试材料」）。
- **用户确认应用只表示采用该版本**，**不自动**升级为已验证事实，也不表示试点已完成。

---

## 12 · 证据版本粒度

- **一次确认应用 = 一个证据版本**（不把一份文件自动拆多个版本）。
- 每个版本**记录**：文件内容**哈希**；**解析与校验规则版本**；**用户声明的覆盖范围**；**文件实际包含的范围**；**来源、合成标识与确认状态**；**计算结果及前一版本引用**。
- **同一文件**若**覆盖范围或解释发生变化**，也形成**新版本**（不覆盖旧的）。
- **门店 / 日期筛选属于版本内视图**，**不**拆成独立版本。
- **撤回只恢复上一证据版本及其派生结果**，**不抹去历史**。
